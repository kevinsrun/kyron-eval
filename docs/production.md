# Production priorities

Current receptionist continuation remains a local fictional read-only demonstration. Full name/DOB plus phone is the configured test policy, not a validated clinical identity standard. Before real use, independently review identity extraction, disclosure authorization, provider-specific availability and concurrency contracts, exact-slot consent receipts, durable idempotency, lifecycle-safe rescheduling/recovery, access controls and clinical routing. No free-slot provider or live mutation approval was established here. The existing appointment calendar must never be interpreted as available-time discovery. See [current recording boundaries](receptionist-recording.md).

The local prototype answers whether evidence supports a claim. At thousands of calls per day, the first production work is making that evidence complete and appropriately protected.

1. **Ingest independently verifiable effects.** Normalize conversation turns, tool attempts, retries, transaction IDs, downstream commit/read receipts, queue acceptance and actual human/transfer acceptance into a versioned event schema. Link events by call and operation IDs. Track ingestion completeness and late events; missing evidence stays UNKNOWN until its collection window closes. A queue acknowledgment and an accepted human handoff are separate effects. Customer EHR adapters need capability-tested write/read contracts, idempotency keys and reconciliation, not optimistic SDK response assumptions.

2. **Freeze comparison inputs.** Store tenant policy revision/checksum, scenario/dataset revision, agent/prompt/model/tool versions, simulator version, evaluator/rubric version, code revision and raw judgment. Keep immutable artifacts in object storage and indexed metadata in a transactional database. Rescoring creates a new evaluation revision referencing the same trace, never overwrites the original. Define explicit migrations and preserve original content hashes so annotations survive reader-schema changes.

3. **Separate protected evidence from telemetry.** Authenticate users, enforce tenant-scoped authorization, encrypt storage and transport, apply retention/deletion controls and audit evidence access. Redact or tokenize identifiers before evaluator ingestion. Store necessary dialogue/tool evidence in a restricted review tier. Operational telemetry carries stable IDs, policy/rule IDs, effect statuses and error codes, not raw statements or tool payloads. The local synthetic-only app's unauthenticated loopback server is not a production access model.

4. **Create a review queue with owners.** Send possible safety violations, unsupported completion claims and evaluator/ingestion errors to an accountable reviewer. Sample UNKNOWN cases, cases where judges disagree, and a random control set; retain sampling probabilities so reviewed failure rates are not mistaken for prevalence. Preserve original labels, reviewer identity, rubric and rationale, resolve disagreements through adjudication and measure inter-reviewer agreement. Do not let an AI-generated label become a human label through relabeling.

5. **Use evidence-based release gates.** Hard deterministic gates should cover terminal emergency invariants, confirmation, matching mutation state and no unsupported completion claims. Keep completion and burden/clarity separate. Block a release on newly introduced critical violations in the regression suite; compare against the same fixture and policy versions. Require review of UNKNOWN and evaluator ERROR cases instead of averaging them into a passing score. A tiny synthetic suite cannot establish a production safety threshold.

6. **Monitor evaluator drift and act on findings.** Maintain a blinded holdout set with human labels and paraphrases, report uncertainty and performance by customer/workflow/language, and periodically review judge abstention and disagreement. Shadow evaluator revisions before promotion; retain old raw judgments for comparison. Track evaluation cost and latency, use deterministic state checks first, and reserve optional language judges for ambiguous cases. Group failures by mechanism and link a reproducible evidence bundle to owned engineering work; close it only after replay/regression verification and monitored rollout evidence.

Before estimating real-world prevalence or promising an intervention's effect, collect representative production calls with appropriate consent and controls, complete downstream state evidence, known policy versions, sampling weights and independently adjudicated human outcomes. Clinicians must own real triage policy content and review. The synthetic rule here is not a basis for production clinical behavior.


## EHR upgrade: concrete next boundaries

The mock path establishes mock persistence only. This integration branch additionally verifies authenticated reads, creation and deletion in a real, isolated OpenEMR 7.0.4 database containing fabricated records. This does not establish production compatibility; validate each customer resource profile, scope, identity mapping and freshness contract separately. Replace synthetic-prefix/tag assumptions with a reviewed adapter-specific trust boundary; do not relax them to admit real records in this take-home. Capability discovery does not authorize mutations. Add supported writes only behind independently verified transaction/readback contracts, bounded retries, idempotency and reconciliation. Handle pagination, appointment status lifecycles, timezone mapping, concurrent updates and intermediate read receipts explicitly.

The optional model is barred from generic external FHIR data; only normalized fields from the explicitly isolated synthetic OpenEMR instance are additionally allowed. A real clinical model path would require a separate privacy/security and clinical-policy design; do not turn on FHIR+LLM by removing one check. Keep tool allowlisting and patient/consent/policy validators outside model prompts. Add per-run wall-clock and token/cost ceilings, cancellation, model-specific compatibility checks and representative actual model experiments. Persist prompt/model/tool/provider versions and raw ordinary responses, while excluding secrets and hidden reasoning.

The retained audit outcome contract has no UNKNOWN: uncertain writes are ATTEMPTED telemetry, with detailed UNKNOWN outcomes in restricted evaluation artifacts. A production event schema should represent uncertainty directly. The local application has no authentication, CSRF/tenant controls, protected-data storage or remote multi-user server hardening; keep it on loopback with synthetic evidence. The existing scenarios and four labels cannot certify clinical safety or model reliability.

## Limits learned from actual OpenEMR

The pinned API has no Slot/Schedule endpoint, and its native cancellation physically deletes a calendar event. These semantics cannot serve as a general clinical scheduling service. Real deployment needs reviewed availability, appointment lifecycle and concurrency contracts, appropriate authorization-code/service authentication, least-privilege roles, and independent reconciliation. The local password grant and synthetic admin role exist only to make this disposable test stack reproducible. No credentials or real records may be migrated into it.

The local SQLite journal protects only operations that reuse the same logical namespace and key. It cannot prevent a user from creating a duplicate in a new run, external writers, or a server commit after a process crash without readback reconciliation. Complete paginated reads, multi-operation receipts, durable recovery workers and appointment uniqueness rules remain unimplemented. The real experiment intentionally labels client-side fault injection; it is not evidence of OpenEMR fault tolerance under real outages.

## Triage validation continuation limits

Public reference agreement is not a clinical release gate by itself. CARE-Bench construction is AI-assisted and human-reviewed; Sen2Med has clinician annotations and disagreement but distinct binary tasks, patient-derived sources and conflicting license statements. Resolve access/licensing and privacy before expanding use; local data must never silently enter voice/model prompts. Keep source cases, prefixes, perturbations and encounters grouped across partitions. Freeze any fitted model/protocol before a genuinely held-out evaluation, calibrate only on development data and obtain independent clinical adjudication.

The live demonstration's conservative keyword/quote policy is incomplete and unvalidated, and its first actual microphone call uncovered an ASR revision failure. Real ASR updates need versioned supersession and uncertainty, clinician-owned red-flag rules and monitored human fallback. Model labels never grant mutation authority. No live scheduling or cancellation is enabled here; unsupported availability, unverified handoffs and unavailable review state remain explicit. Genuine WebRTC evidence is browser-reported decoded audio plus network callbacks, not a signed receipt, PSTN test or clinical-performance measurement.
