# Production priorities

The local prototype answers whether evidence supports a claim. At thousands of calls per day, the first production work is making that evidence complete and appropriately protected.

1. **Ingest independently verifiable effects.** Normalize conversation turns, tool attempts, retries, transaction IDs, downstream commit/read receipts, queue acceptance and actual human/transfer acceptance into a versioned event schema. Link events by call and operation IDs. Track ingestion completeness and late events; missing evidence stays UNKNOWN until its collection window closes. A queue acknowledgment and an accepted human handoff are separate effects. Customer EHR adapters need capability-tested write/read contracts, idempotency keys and reconciliation, not optimistic SDK response assumptions.

2. **Freeze comparison inputs.** Store tenant policy revision/checksum, scenario/dataset revision, agent/prompt/model/tool versions, simulator version, evaluator/rubric version, code revision and raw judgment. Keep immutable artifacts in object storage and indexed metadata in a transactional database. Rescoring creates a new evaluation revision referencing the same trace, never overwrites the original. Define explicit migrations and preserve original content hashes so annotations survive reader-schema changes.

3. **Separate protected evidence from telemetry.** Authenticate users, enforce tenant-scoped authorization, encrypt storage and transport, apply retention/deletion controls and audit evidence access. Redact or tokenize identifiers before evaluator ingestion. Store necessary dialogue/tool evidence in a restricted review tier. Operational telemetry carries stable IDs, policy/rule IDs, effect statuses and error codes, not raw statements or tool payloads. The local synthetic-only app's unauthenticated loopback server is not a production access model.

4. **Create a review queue with owners.** Send possible safety violations, unsupported completion claims and evaluator/ingestion errors to an accountable reviewer. Sample UNKNOWN cases, cases where judges disagree, and a random control set; retain sampling probabilities so reviewed failure rates are not mistaken for prevalence. Preserve original labels, reviewer identity, rubric and rationale, resolve disagreements through adjudication and measure inter-reviewer agreement. Do not let an AI-generated label become a human label through relabeling.

5. **Use evidence-based release gates.** Hard deterministic gates should cover terminal emergency invariants, confirmation, matching mutation state and no unsupported completion claims. Keep completion and burden/clarity separate. Block a release on newly introduced critical violations in the regression suite; compare against the same fixture and policy versions. Require review of UNKNOWN and evaluator ERROR cases instead of averaging them into a passing score. A tiny synthetic suite cannot establish a production safety threshold.

6. **Monitor evaluator drift and act on findings.** Maintain a blinded holdout set with human labels and paraphrases, report uncertainty and performance by customer/workflow/language, and periodically review judge abstention and disagreement. Shadow evaluator revisions before promotion; retain old raw judgments for comparison. Track evaluation cost and latency, use deterministic state checks first, and reserve optional language judges for ambiguous cases. Group failures by mechanism and link a reproducible evidence bundle to owned engineering work; close it only after replay/regression verification and monitored rollout evidence.

Before estimating real-world prevalence or promising an intervention's effect, collect representative production calls with appropriate consent and controls, complete downstream state evidence, known policy versions, sampling weights and independently adjudicated human outcomes. Clinicians must own real triage policy content and review. The synthetic rule here is not a basis for production clinical behavior.
